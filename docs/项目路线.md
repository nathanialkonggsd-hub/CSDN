# 项目路线

> **核心原则：项目先行，文章跟随。**
>
> 文章不是为了凑数量，而是项目真实推进后的实验记录、技术复盘与阶段总结。

## 🚀 当前主线：STM32 + TinyML

当前阶段暂不以新增文章数量为目标，优先推进 **STM32 + TinyML 端侧手势识别系统**。

第一阶段已经完成从传感器到 MCU 推理的基本闭环：

```text
MPU6050
   ↓
STM32F103ZET6 数据采集
   ↓
Python / CSV 数据集
   ↓
Edge Impulse 模型训练
   ↓
TinyML 模型部署
   ↓
STM32 端侧推理
   ↓
OLED 显示识别结果
```

### 第一阶段已经验证的能力

- MPU6050 驱动与 I²C 通信
- 三轴加速度数据采集
- STM32 → USART → PC 数据链路
- Python 自动保存 CSV 数据集
- Edge Impulse 数据处理与模型训练
- TinyML 模型生成与 STM32 部署
- STM32 端侧实时推理
- OLED 输出识别结果

### 第二阶段目标

第二阶段不直接“空写 79 篇”，而是先完成真实实验：

```text
扩大数据集
   ↓
数据质量检查
   ↓
训练 / 验证 / 测试集重新设计
   ↓
V3 模型训练
   ↓
混淆矩阵与低置信度样本分析
   ↓
模型优化
   ↓
重新部署 STM32
   ↓
真实设备测试
   ↓
形成实验结果
   ↓
再写第 79 篇
```

重点从“能跑”转向：

> **更稳定、更可靠、更能泛化。**

## 项目三：数据结构可视化

**来源：** 17、19、44–70。

将已经完成的数据结构与算法文章转化为可交互项目：

- 链表：插入、删除、遍历动画

## 🧭 项目推进规则

### 规则 1：项目进度优先于文章进度

没有新的代码、实验、数据、测试结果，就不为了编号而强行写文章。

### 规则 2：文章必须对应真实进展

每一篇后续文章至少应该有一个真实产出：

- 新功能
- 新实验
- 新数据
- 新模型
- 新测试结果
- Bug 修复
- 性能优化
- 阶段性结论

### 规则 3：先做实验，再决定文章内容

后续文章标题可以根据实际项目进度调整，不为了提前规划的标题牺牲真实性。

### 规则 4：一个阶段只保留一个主项目

当前主项目明确为 **STM32 + TinyML**，其他项目进入候选池，不并行消耗主要精力。

### 规则 5：最终形成“项目 → 实验 → 数据 → 代码 → GitHub → 文章”的闭环

```text
项目推进
   ↓
实际实验
   ↓
产生数据 / 代码 / 结果
   ↓
提交 GitHub
   ↓
技术复盘
   ↓
CSDN 文章
```

这套流程比单纯持续增加文章数量更重要。
