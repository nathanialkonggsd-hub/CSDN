## 1. 核心概念：文件与“流” (Stream)

在动手写代码前，我们得先搞清楚 C 语言是怎么看待文件的。

### 什么是“流”？
试想一下，键盘输入、屏幕输出、硬盘读写、网络传输，这些设备的底层硬件差异极大。如果 C 语言要为每种设备写一套专属的读写代码，那编译器早就罢工了。

为了偷懒（划掉，为了优雅），C 语言的大佬们抽象出了一个概念——**流 (Stream)**。
你可以把“流”想象成一根**水管**。无论水管的一头接的是硬盘、屏幕还是网络，作为程序员，我们只需要把数据像水一样“倒”进管子里，或者从管子里“接”水。至于底层是怎么流过去的，C 语言标准库全帮你搞定了。

> **冷知识：**
> 任何 C 程序运行起来时，都会默认帮你打开三个流：
> - `stdin` (标准输入流：默认连着键盘)
> - `stdout` (标准输出流：默认连着屏幕)
> - `stderr` (标准错误流：默认连着屏幕)
> 
> 我们天天用的 `printf` 和 `scanf`，其实就是在对 `stdout` 和 `stdin` 这两个流进行操作！

## 2. 开启大门：FILE 指针与文件的打开/关闭

在 C 语言中，操作文件的第一步，是拿到这扇门的“钥匙”——`FILE` 指针。

### 2.1 FILE 结构体
`FILE` 其实是 C 语言底层定义好的一个**结构体类型**，里面记录了文件的名字、状态、当前读写到了哪个位置等各种内部信息。我们不需要深究它里面长什么样，只需要记住：**操作文件，就靠 `FILE*` 指针。**

### 2.2 敲门砖：`fopen`
要读写文件，必须先打开文件。

```c
FILE * fopen ( const char * filename, const char * mode );
```
- `filename`: 文件路径（比如 `"data.txt"` 或 `"C:\\Users\\test.txt"`）
- `mode`: 打开模式（读？写？还是追加？）

**核心打开模式速查表（必备）：**

| 模式 | 含义 | 如果文件不存在 | 如果文件已存在 |
| :---: | :--- | :--- | :--- |
| `"r"` | **只读** (Read) | ==打开失败，返回 NULL== | 从头开始读 |
| `"w"` | **只写** (Write) | 自动创建新文件 | ==清空原内容==，从头开始写 |
| `"a"` | **追加** (Append) | 自动创建新文件 | 在原内容末尾接着写 |
| `"r+"`| **读写** (Read/Write) | 打开失败，返回 NULL | 从头开始读写，不强制清空 |
| `"w+"`| **读写** (Write/Read) | 自动创建新文件 | ==清空原内容==，从头开始读写 |
| `"a+"`| **读写追加** (Append/Read)| 自动创建新文件 | 读从头读，写必定在末尾追加 |

### 2.3 关门大吉：`fclose`
就像 `malloc` 之后必须 `free` 一样，文件用完了**必须**关闭！如果不关，可能会导致数据还在内存缓冲区里没来得及刷到硬盘上，从而造成数据丢失。

```c
int fclose ( FILE * stream );
```

**一套标准的文件操作起手式：**

```c
#include <stdio.h>

int main() {
    // 1. 打开文件
    FILE *pf = fopen("test.txt", "w");
    
    // ⚠️ 极其重要的防翻车检查！
    if (pf == NULL) {
        perror("文件打开失败"); // 打印错误信息
        return 1;
    }

    // 2. 读写文件（稍后展开）
    // ... 

    // 3. 关闭文件
    fclose(pf);
    pf = NULL; // 好习惯：防止野指针

    return 0;
}
```

## 3. 基础读写：单字符与字符串

### 3.1 细水长流：`fputc` 与 `fgetc` (单字符)
顾名思义，`put character to file` 和 `get character from file`。

```c
// 向文件写一个字符
fputc('A', pf);

// 从文件读一个字符（如果读到文件尾或出错，返回 EOF）
int ch = fgetc(pf);
```

### 3.2 大口吞咽：`fputs` 与 `fgets` (字符串)
一个一个字符写太慢了，我们通常按行读写。

```c
// 写入字符串
fputs("Hello, Hardcore C!\n", pf);

// 读取字符串
char buf[100];
// 从 pf 中读取最多 99 个字符存入 buf（自动补 '\0'），遇到换行符提前结束
fgets(buf, 100, pf); 
```
> **排雷提示**：`fgets` 是一个极其安全的函数，它不仅会防止数组越界（通过传入参数 100 限制），还会**把换行符 `\n` 也一起读进数组里**。处理数据时千万要注意那个偷偷藏在末尾的换行符。

## 4. 格式化读写：`fprintf` 与 `fscanf`

看到这两个函数，是不是觉得很眼熟？没错，它们就是 `printf` 和 `scanf` 的亲兄弟，仅仅是在前面多了一个 `f` (File)。

还记得上一篇我们定义的图书结构体吗？如果我们想把它存进文件，这两个函数简直是神器：

```c
struct Books {
   char title[50];
   int  book_id;
   float price;
};

// ... 假设已打开文件 pf (模式 "w") 和结构体变量 book1
// 写法和 printf 一模一样，只是把流指针 pf 放在第一个参数！
fprintf(pf, "%s %d %.2f\n", book1.title, book1.book_id, book1.price);
```

读取的时候同样丝滑（假设文件内容为：`C-Primer 666 88.50`）：

```c
// ... 假设已打开文件 pf (模式 "r")
fscanf(pf, "%s %d %f", book1.title, &book1.book_id, &book1.price);
```
**一句话总结：`fprintf/fscanf` 可以把各种类型的数据格式化为字符串写进文本，又能把文本里的字符串扒出来还原成各种类型。**

## 5. 附赠神技：内存中的格式化 `sprintf` 与 `sscanf`

既然讲到了格式化函数家族，就不得不提这对虽然不操作硬盘文件，但极其好用的“字符串处理刺客”。

它们不针对屏幕(`stdout`)，也不针对文件(`FILE*`)，而是直接**针对内存中的字符串数组**进行读写。前面变成了 `s` (String)。

### `sprintf`：将数据打包成字符串
```c
char buf[100];
int age = 20;
float score = 98.5;
// 把后面的格式化数据，全部拼接成字符串存进 buf 中
sprintf(buf, "Age:%d, Score:%.1f", age, score); 
// 此时 buf 里的内容就是 "Age:20, Score:98.5"
```

### `sscanf`：从字符串中提取数据
```c
char data[] = "User:Tom ID:9527";
char name[20];
int id;
// 从 data 字符串里，按照指定格式把数据“抠”出来
sscanf(data, "User:%s ID:%d", name, &id);
```
在处理网络报文、解析复杂日志字符串的时候，这对兄弟能让你少写几百行 `for` 循环和字符串截取代码！
