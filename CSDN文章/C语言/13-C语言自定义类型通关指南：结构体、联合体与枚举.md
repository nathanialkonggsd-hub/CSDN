## 1. 结构体 (Struct)：数据的“豪华拼盘”

C 语言的基本类型就像是超市里散装的苹果、香蕉，虽然好吃但不好拿。结构体则是把这些散装货打包成“豪华水果篮”的工具。

### 1.1 语法：如何“扎”一个水果篮？

> **结构体** 是一种可以将不同类型的数据组合在一起形成一个新的数据类型的语法结构。

```c
// 定义一个名为 Books 的结构体类型
struct Books {
   char  title[50];    // 书名（字符数组）
   char  author[50];   // 作者
   char  subject[100]; // 标题
   int   book_id;      // 书 ID（整型）
};
```

这里我们只是定义了一个“模具”。要使用它，得实例化：

```c
// 定义结构体变量 book1
struct Books book1; 

// 也可以直接在定义类型时紧接着定义变量（虽然不常用，但得知道）
struct Point {
    int x;
    int y;
} p1, p2;
```

### 1.2 访问与初始化：水果篮里的苹果怎么拿？

访问结构体成员有两种武器：

1. **`.` 运算符**：用于具体的变量。(>下面的符号)
2. **`->` 运算符**：用于结构体指针。(-与>)

```c
#include <stdio.h>
#include <string.h>

struct Books {
   char title[50];
   int  book_id;
};

int main() {
   struct Books book1;        // 定义变量
   struct Books *ptr = &book1;// 定义指针

   // 初始化操作
   strcpy(book1.title, "C Programming"); // 使用 . 操作符
   ptr->book_id = 66666;                 // 使用 -> 操作符

   printf("书名: %s, ID: %d\n", book1.title, ptr->book_id);

   return 0;
}
```

> **面试官：请问下面这个结构体占多少字节？**

```c
struct S1 {
    char c1;
    int i;
    char c2;
};
```

如果你回答 `1+4+1=6`，恭喜你，得到了一个大大的“X”。实际结果往往是 **12**。

为什么？因为 **CPU 读取内存是有偏好的**。它喜欢在 4 字节或 8 字节的整数倍地址开始读。如果数据东倒西歪地躺在内存里，CPU 读起来效率极低，甚至报错。为了迎合 CPU，编译器会默默地进行“内存对齐”。

#### 对齐规则（总结版）：

1. **首成员**：放在相对于结构体首地址偏移量为 0 的地方。
2. **其他成员**：要对齐到 **对齐数** 的整数倍地址处。
   * `对齐数 = min(编译器默认对齐数, 成员自身大小)`。（VS 默认 8，Linux 默认 4 或 8）。
3. **总大小**：必须是 **最大对齐数**（所有成员最大对齐数与默认对齐数的较小值）的整数倍。

咱们来实战分析 `struct S1`（假设默认对齐为 8）：

| 成员 | 大小 | 自身对齐数 | 默认对齐数 | 有效对齐数 | 存放位置（偏移量） | 说明 |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| `c1` | 1 | 1 | 8 | 1 | `0` | 占用偏移量 0 |
| `padding`| - | - | - | - | `1, 2, 3` | 为了让 `i` 对齐，浪费 3 字节 |
| `i` | 4 | 4 | 8 | 4 | `4 ~ 7` | 对齐到 4 的倍数地址 |
| `c2` | 1 | 1 | 8 | 1 | `8` | 占用偏移量 8 |
| `padding`| - | - | - | - | `9, 10, 11` | 总大小 `9` 不是最大对齐数(4)倍数，补齐 |

**总大小 = 12 字节。** 浪费了 6 字节！

#### 如何节省空间？

让小弟（大小小的成员）站在一起。

```c
struct S2 {
    char c1;
    char c2;
    int i;
};
```

这样一改，`struct S2` 的大小就变成了 **8 字节**。不信你可以自己在 IDE 里 `sizeof` 试试。

## 2. 联合体 (Union)：内存的“共享单车”

结构体是“豪华拼盘”，每个人都有自己的位子；联合体则是“共享单车”，大家共享同一个位子，但同一时间只能有一个人骑。

### 2.1 语法与特性：内存魔术师

> **联合体**（也叫共用体）允许在相同的内存位置存储不同的数据类型。

```c
#include <stdio.h>

// 定义联合体类型
union Data {
   int i;
   float f;
   char str[20];
};

int main() {
   union Data data;

   // 关键：联合体的大小是其最大成员的大小
   printf("sizeof(Data): %lu\n", sizeof(data)); // 输出 20

   data.i = 10;
   data.f = 220.5; // data.i 的值此时已被覆盖！

   return 0;
}
```

### 2.2 深度理解：同床异梦

联合体的内存布局是所有成员都 **从同一个首地址开始存放**。

```c
union Test {
    char a;
    int b;
};
```

如果我们写 `test.b = 0x12345678;`，那么内存布局（小端模式）大约是这样的：

* `0x12` (高地址)
* `0x34`
* `0x56`
* `0x78` (首地址)

此时如果我们访问 `test.a`，只能拿到首地址的 `0x78`。这种特性常用于需要 **把同一块数据以不同视角看待** 的底层开发中（比如判断大端小端模式）。

> **警告**：访问非最后一次赋值的成员，得到的结果往往是“不可预料的垃圾值”。

## 3. 枚举 (Enum)：让代码告别魔术数字 (Magic Numbers)

在没有枚举之前，我们描述状态往往是这样的：

```c
#define SUCCESS 0
#define FAILED 1
#define UNKNOWN 2

int state = SUCCESS;
```

这不仅麻烦，而且编译器根本不认识 `SUCCESS`，在调试时只给你显示个 `0`。枚举解决了这个问题。

### 3.1 语法：给数字起个好听的名字

> **枚举** 是一组命名的整数常量。

```c
#include <stdio.h>

// 定义枚举类型 Day
enum Day {
    MON = 1, // 显示指定初始值为 1
    TUE,     // 自动默认为 2
    WED,     // 自动默认为 3
    THU = 100,// 显示指定为 100
    FRI,     // 自动默认为 101
    SAT,
    SUN
};

int main() {
    enum Day today = WED;

    if (today == 3) { // 既可以使用名字，编译器底层也认识数字
        printf("今天是周三！\n");
    }

    printf("WED 的底层数字是: %d\n", today); // 输出 3
    printf("FRI 的底层数字是: %d\n", FRI);   // 输出 101

    return 0;
}
```

枚举默认从 `0` 开始递增。它大大增强了代码的可读性和可维护性。

## 4. 总结与下期预告

我们用一张表格来回顾一下：

| 类型 | 内存布局特性 | 关键点 | 适用场景 |
| :--- | :--- | :--- | :--- |
| **Struct** | 成员依次排放，**每个人都有独立空间** | **内存对齐** (浪费空间换效率) | 描述复杂对象 (如学生、汽车) |
| **Union** | 所有成员共享**同一块首地址内存** | **空间复用** (同一时间只能用一个成员)| 节省空间、位域操作、大小端判断 |
| **Enum** | 编译器底层的 **`int` 型常量** | 代码可读性、状态码定义 | 定义有限的状态、月份、一周天数 |
