## 敲代码 vs 烧板子：感觉真的不一样

毕竟是第一次摸硬件，我的新手打怪路线定得很保守：**从 51 单片机开始，以后再过渡到 STM32。**

不为别的，就为了先把底层的硬件逻辑大概摸透。一口吃不成个胖子，慢慢来。

不过刚上手就发现，纯写代码和搞硬件的心态完全不同。纯写软件时，错了大不了看报错、改 Bug、重新编译；但现在连硬件，得多考虑一层物理上的东西：排线有没有插对？电压够不够？短路了没？

有一种从“纯脑力活动”变成了“手工课 + 脑力活动”的新鲜感，当然，受挫感也跟着翻倍了。我手头这块 51 开发板，第一印象就是排针密密麻麻，看着挺头大，还附带了一堆跳线和面包板，感觉桌子都不够用了🤷‍♂️。

## 给新手的避坑指南：大白话理解点灯逻辑

为了测试板子好不好使，第一步当然是写个 C 语言程序点亮 LED 灯。这里给跟我一样刚入门的同学分享一下我的理解。别去死记硬背芯片手册里的生硬定义，咱们换个思路。

### 1. 什么是 GPIO 引脚配置？
你就把单片机想象成一个长了很多只手的大脑，这些手就是“引脚”（GPIO）。

但这些手一开始是懵的，你必须在写代码时先给它们分派任务：你是要“往外使劲”（输出模式，比如去推亮一盏灯），还是要“往里收东西”（输入模式，比如去感受按钮有没有被按下）。

配置 GPIO，说白了就是你在上岗前，挨个告诉这些引脚：**“你，去负责输出供电；你，去负责听按钮的指令。”**
![在这里插入图片描述](https://i-blog.csdnimg.cn/direct/33c897380c44408abb9ceb0f004bd9c2.png)

### 2. 为什么要用 While 循环点灯？
单片机是个超级老实、但记性很差的打工人。如果你只写一句代码告诉它“把灯打开”，它瞬间做完这事儿后，程序就结束了，板子就“罢工”了。

为了让它一直工作，我们就得用一个死循环 `while(1)` 把任务框起来。这就相当于给它下了一道死命令：**“只要板子还有电，你就给我一直盯着这盏灯，永远不准停。”**

### 最简 C 语言示例代码
下面是一段带注释的最基础点灯代码，跑在 51 单片机上：

> 注：这里代码适配STC89C51/52系列，具体头文件，引脚请参考开发手册

```c
#include <reg52.h> // 引入单片机的头文件，让代码认识板子上的零件
tepydef unsigned int u16;
sbit LED = P2^0;   // GPIO配置：给单片机P2那一排的第0个引脚起个外号，叫LED

// 写个简单的延时函数，相当于让单片机在这里“数羊”发呆
// 不然它动作太快，灯闪得人眼根本看不出来
void delay_10us(u16 ten_us) {
    while(ten_us--); 
}

void main() {
    // 只要条件是1（永远为真），这个循环就会一直跑下去，直到拔电源
    while(1) { 
        LED = 0;      // 往外使劲（输出低电平），电路接通，灯亮起
        delay(50000); // 别急着灭，发呆等一会儿
        
        LED = 1;      // 断开（输出高电平），电路断开，灯熄灭
        delay(50000); // 保持熄灭状态再等一会儿
    }
}
```

## 挖个坑：以后想折腾点啥？

说实话，硬件这摊子水挺深的。我对这段学习的期望也不高：不求马上就能搞出多炫酷的发明，只要能搞懂单片机是怎么控制外围电路的，以后遇到 Bug 知道该拿万用表测哪里，就算是胜利。

不过，我也给自己立了个小小的 Flag。平时专业课里没少算温度、风速这些气象数据，以后等我技术熟练点，我想自己焊一个**迷你的气象环境监测站**。

计划连上温湿度传感器和风速小模块，把测到的实时天气数据直接显示在一块小屏幕上。不求多专业，能跑通整个流程就行。
